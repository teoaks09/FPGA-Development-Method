# LLM wiki schema

Purpose: let an LLM session understand this project without reading all code and PDFs, both
during development (compiled knowledge instead of raw documents) and later (when a feature is
added and the old sessions are gone). Pattern: Karpathy's "LLM Wiki" - sources are compiled once
into small interlinked pages; questions are answered from the pages.

## Layers
- `llm/raw/` - sources, never edited. `sources.md` lists them; copyrighted files live in
  `llm/raw/local/` (git-ignored).
- `llm/wiki/` - pages owned by the LLM.
- This file - the rules.

## Page format
```
---
title: <title>
type: codemap | xilinx | protocol | concept | lesson
status: unverified | verified | generated
sources: [<doc no> <version> §<section>, ...]
---
```
- One topic per page, short. Link related pages with relative links.
- Facts from documents cite document number + version + section.
- New facts from a free model are `status: unverified`; they become `verified` when confirmed in
  simulation/synthesis or reviewed by Claude.

## Folders
- `codemap/` - one card per RTL module; the Interface section is generated by `make codemap`,
  Purpose and Notes are written by the wiki maintainer.
- `xilinx/` - facts about the Xilinx IP used, per Vivado version.
- `protocols/` - protocol facts needed by the design.
- `lessons/` - instructive debug results and distilled problem reports.

## Operations
- ingest <source> [sections]: read only the requested sections, write/update pages, update
  index.md, append to log.md.
- query <question>: read index.md, then only the pages needed; answer with page links.
- lint: `make wiki-lint`; fix mechanical issues; report contradictions to the user.

## When
- Before working on a Xilinx IP or protocol: ingest the relevant sections.
- After a feature is added or its interface changes: `make codemap` + Purpose/Notes.
- After an instructive debug: a lesson page.
